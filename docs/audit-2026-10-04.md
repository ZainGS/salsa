## Part 2 — New findings

### Robustness

1. **High · The frame's canvas texture is held across an `await`** *(verified)* — `getCurrentTexture()` at
   `renderer/core/webgpu-renderer.ts:1980`, then `await this._rasterCompositor.compositeAsync(...)` at `:2060` / `:2484`
   (waits on `mapAsync`, `raster/effects/dither-engine.ts:469`), then the texture is written at `:2626`. Per spec the
   canvas texture expires when the task yields → dropped frames / validation errors for documents using error-diffusion
   dither. Fix: acquire the texture after the last await, or run the async dither before recording.
2. **Med · Silent render failures** — `_renderLive` does `p.then(endFrame, endFrame)` with no logging
   (`webgpu-renderer.ts:705`). Any exception in a live frame disappears.
3. **Med · Sync pipeline compile can't detect failure** — `GPUPipelineCache._compileSync` wraps sync
   `createRenderPipeline` in try/catch (`core/gpu-pipeline-cache.ts:329-334`); it doesn't throw on validation errors, so
   an invalid pipeline is published as ready and retry/backoff never fires. Wrap in a validation error scope.
4. **Med · 2D pipelines bypass the cache** — `PipelineManager` compiles ~17 pipelines synchronously in its constructor
   (`core/managers/pipeline-manager.ts:28-47`) + 14 sync creations in `shell-renderer.ts`: no async compile, no failure
   handling, startup stalls.
5. **Med · Two persistence stacks** — `sm.persistence` (`_createPersistence`, `services/shape-manager.ts:13394`) and
   `sm.persist._persistence` (`services/managers/persistence-manager.ts:39-61`) each have `enableAutoSave`,
   `loadDocument`, `currentDocId`. If a host uses both: two autosave timers on one document, ids can drift.
6. **Med (likely) · Save-indicator callbacks dropped** — `onSaveEvent` (:13455) sets callbacks on the current instance;
   `enableAutoSave` (:13417-13418) replaces the instance and `_createPersistence` doesn't re-apply them → "Saving…/Saved"
   UI can go silent after a document switch.
7. **Low · Teardown leaks** — `GizmoRenderer.destroy()` misses ~10 buffers (`3d/gizmo-renderer.ts:1330-1370, 1637` vs
   `:2648`); `gpu-scene.ts` never destroys `_shFrameBuf` (:431 vs :1033); artboard bind group rebuilt every draw
   (`gizmo-renderer.ts:1661`). Mesh shader variants (`3d/pipeline-3d.ts:249-278`) have no cap/eviction.
8. **Low · Events** — 31 `EventEmitter`s, ~9 hand-rolled listener `Set`s, 14 `on*()` methods on ShapeManager with three
   contracts (`onSaveEvent` returns void and replaces), ~100 single-slot `onX` fields. `EventEmitter.emit`
   (`renderer/util/event-emitter.ts:11`) has no try/catch — one throwing listener stops the rest.
9. **Low · Workers** — envelope typed (`worker-job-runtime.ts:40-50`) and errors/crashes reject jobs (good), but
   `run<I,O>(kind: string)` (:185) lets callers assert types unrelated to the kind; no `onmessageerror` → an undecodable
   result hangs the job; errors cross as strings.

### Architecture

    - 11 cycles over 81 files counting type imports; the largest is 34 files (27 `services/managers` + 7 `renderer`,

### Library, build, docs

20. **High · Package metadata and README are wrong** *(verified)* — `package.json`: "A 2D vector rendering library",
    keywords `2d, vector, webgl`, ISC, 0.0.1, no changelog. README: "Salsa Vector Renderer", "as of 2024", wrong install
    names (`@frogmarks/salsa`, `@zain/salsa`), `import { Salsa }` (doesn't exist), says MIT "see LICENSE" — there is no
    LICENSE file. If it will never be published, set `"private": true`.
21. **Med · No versioned contract with Frogmarks** — `file:` link, 0.0.1, no changelog; Frogmarks guards 52 engine calls
    with `?.()` "for older dists". → semver + CHANGELOG + an exported `SALSA_API_VERSION` Frogmarks checks once at boot.
22. **Med · CI never builds the library** — deliberate, but the `vite build + tsc + write-dts-stubs` chain and the `dist`
    Frogmarks links are never verified. → CI job: build, smoke-import the 3 entries from `dist`, tsc against `dist/*.d.ts`.
23. **Med (likely) · `exports` condition order** — `import`/`require` before `types` in every entry; TS wants `types`
    first (under bundler/node16 it may look for `main.es.d.ts`). Move `types` first.
24. **Med · `wasm/` is a heavy dependency for little** — the crate is 291 lines of CPU error-diffusion dithering, used only by
    `dither-engine.ts` (which skips the effect when wasm isn't ready). It needs a Rust + wasm-pack toolchain and a
    hand-committed `wasm/pkg` (CI warns wasm-pack writes a `*` `.gitignore` into it). `wasm-package: file:wasm/pkg` is
    imported by nothing (code uses a relative path). → port to TS or a compute shader and delete `wasm/`; at minimum drop
    the unused dependency.
25. **Med · Bleeding-edge toolchain on caret ranges** — TS `^7.0.2`, rolldown-vite `^7.3.1` (forced via overrides),
    vitest `^5.0.2`; lint runs a separate TS 5.9 (`tools/lint`), so `tsc` and type-aware lint can disagree. Root `eslint ^8`
    and `prettier ^2` are unused. → pin exact versions; keep the lockfile committed.
26. **Med · Uneven test coverage** — 335 files / ~10,050 expects, mostly real behavioural tests (keep it up). Gaps vs code
    size: `renderer/core` 10.2k lines / 4 tests, `renderer/raster` 12.1k / 2, `renderer/shell` 4.7k / 0,
    `services/drawing` 2.8k / 0, `viewer` 0.9k / 0. No test imports `renderer-3d.ts` or `webgpu-renderer.ts`.
    6 "tests" are env-gated dev tools (e.g. `vending-preview.test.ts`, 0 expects); ~350 assertions grep WGSL text.
27. **Low · Build details** — `test-animations.ts` (2 MB) imported only by `main.ts:19` with its use commented out (:208):
    tree-shaken from JS but still type-checked and emitted as `.d.ts` → move to test fixtures, drop the import.
    No JS sourcemaps while `declarationMap` points at `src/` (not in `"files"`); `fflate`/`sucrase` bundled *and* listed
    as dependencies; `write-dts-stubs.mjs` duplicates the vite entry map; `vite.config.ts` comment says esbuild (it's oxc).
28. **Low · Docs sprawl** — 283 md files (specs 130, ui 74, theory 26, reference 25…), 77 linked from nowhere; six dated
    audit/eval docs at the root with no superseded/archive marking; `CONTEXT_3D_ENGINE.md` dated 2026-04-27 and stale.

### Strengths (keep)

- `strict` TypeScript, CI on every push running sanity + tsc + lint + the full suite, one `scripts/check.mjs` for local
  and CI, source-sanity checks, small lint baseline.
- Tests are mostly real (behavioural and invariant tests, no mocks); persistence fixes were mutation-checked.
- `GPUPipelineCache` (async, prioritised, skip-don't-stall, bounded retry, settled-wait), lazy optional 3D passes,
  pooled hot-path data, on-demand frame loop, device-loss recovery design (stable device-proxy handle, ordered owners).
- Little global state (2 `getInstance` singletons), `ManagerContext` DI used by 37 managers, 25 `*Host` interfaces.
- `world/` and `game/` are engine-free and deterministic (seeded RNG; `Math.random` only in runtime behaviour);
  `game/` talks out only through small host interfaces — the model for the other domains.
- The viewer is a clean small consumer (never touches ShapeManager / Scene3DManager / world / packaging).
- All loads go through `restoreDocumentState`; all worker work through `WorkerJobService` with a main-thread fallback.
