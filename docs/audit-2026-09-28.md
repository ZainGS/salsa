# Audit 2026-09-28 — fix list

Independent whole-library audit (5 parallel reviews: persistence, renderer, tooling, architecture, characters), each
checked against code; the worst findings were re-verified by hand. Work top-down — **Tier 1 can lose user data.**

Legend: `[x]` done · `[ ]` open · **S/M/L** = rough effort · line numbers are as of 2026-09-28 and will drift.

---

## Tier 1 — Persistence (data loss / corruption) — ✅ ALL DONE 2026-09-28

- [x] **P0 · GLB prune wipes every model.** `models3d` was only gathered when a 3D mesh was dirty, but pruning ran on
  save #0 and every 8th save with that (empty) keep-set. *Fixed:* `models3dComplete` payload flag; prune `models3d`
  only when true (`document-persistence.ts`, `document-state-coordinator.ts`). **S**
- [x] **P1 · Autosave fires during a document load → writes into the wrong doc.** *Fixed 2026-09-28:*
  `DocumentPersistence.suspend()/resume()` — a hard gate on auto AND explicit saves that also cancels a pending
  stroke-debounce and waits out a save already writing. `ShapeManager.restoreDocumentState` (the one funnel every
  load path uses) suspends both persistence instances for the whole restore, incl. procedural regen. `currentDocId`
  is now set BEFORE the restore (ShapeManager + persist delegate). If the restore THROWS, saving is blocked
  (`setSaveBlocked`) so the partial scene can't overwrite either copy — `sm.getSaveBlockedReason()` /
  `sm.clearSaveBlock()` for the host. 6 tests in `document-persistence.test.ts` (mutation-checked). **M**
- [x] **P2 · A partial load reports success, then autosave overwrites the good copy.** *Fixed 2026-09-28:*
  `DocumentStateCoordinator.restore()` now returns a `RestoreReport` — every one of its ~17 swallow-and-warn catch
  sites records an issue instead. Each 3D mesh restores in its own try/catch (one bad mesh used to drop every mesh
  after it). `setSceneGraphJSON(json, { rethrow: true })` on the load path; raster layers that can't restore are
  recorded. `ShapeManager` pauses autosave when any issue has `blocksSave` (all except procedural regen, whose markers
  still persist). Host API: `sm.getLastRestoreIssues()` + `sm.getSaveBlockedReason()` / `sm.clearSaveBlock()`;
  `RestoreIssue` exported. **Also fixed (save side, same class as P0):** a mesh/face texture that fails to *export*
  no longer gets pruned from disk (`meshTexturesComplete`). 4 tests in `document-state-coordinator.test.ts`. **M**
- [x] **P3 · GARP pools + UI layers never reach OPFS.** *Fixed 2026-09-28:* `writeToOPFS` writes `garp.json` +
  `ui.json` (gzipped via writeText) and `loadDocument` reads them back. Because the gather sends `null` when there are
  none, a null field now DELETES the file — otherwise removing your last pool / UI layer would resurrect it on reload.
  Added `opfs-fake.ts` (in-memory OPFS for tests) + 4 real write→read round-trip tests (also covering P0's prune fix
  and the texture-export prune guard), mutation-checked. *Still open under P6:* a doc with NO pools/UI layers doesn't
  clear the previous doc's in-memory ones on load; `.frogmarks` still omits GARP (P4). **S–M**
- [x] **P4 · `.frogmarks` pack/unpack was a second, drifted save path.** *Fixed 2026-09-28:* package format **v2**
  = the autosave payload itself (`gatherDocumentState(true)`), laid out as the same files as the OPFS folder —
  now carries meshTextures (UV/face/garment/prop paint), bakedParts, GARP, packaging. `unpackProject` restores through
  the ONE normal path (`restoreDocumentState`: same order, load guard, failure report) instead of re-adding meshes and
  wiping regenerated geometry. Export no longer clears the 3D dirty flags. v1 files still import (same scene3d.json
  shape). **Also found + fixed:** OPFS autosave never saved the **kitbash character catalog** (only the .frogmarks
  path did) — `characters` + `gpObjects` now ride scene3dJSON for both; and a doc with **no 3D section** now clears the
  previous doc's 3D on load (OPFS + import). 4 tests in `project-package.test.ts` (all sections round-trip + v1 compat
  + newer-version refusal). *Left:* the public `restoreScene3DNodes` helper still no-ops on an empty list (unused
  by the host). **M**
- [x] **P5 · Dirty-flag race.** *Fixed 2026-09-28:* `Mesh3D.stateDirty` is now an accessor that bumps a monotonic
  `stateVersion` on every `= true` (no call-site changes). A save snapshots `(id, version)` of the dirty meshes before
  serializing; on completion `clearMeshDirtyStateIfUnchanged` clears only those whose version didn't move — an edit
  that lands mid-write stays dirty and is saved next time. 3 tests in `scene3d-dirty-snapshot.test.ts`. **S**
- [x] **P6 · Stale registries survive document load.** *Fixed 2026-09-28:* one unconditional
  `ShapeManager.clearDocumentRegistriesForLoad()` runs FIRST in every restore (failures recorded → blocks save).
  It clears: character rigs (face incl. blink timers / hair / clothing / charms / body params + surfaces), the kitbash
  catalog + baked parts (blob URLs revoked), the GLB model store (refilled per GLB mesh by restoreMeshState — it was
  writing the previous doc's GLBs into the new doc), CD kits, GARP (`GarpManager.clear()`; built-in pools re-seed lazily
  via the resolver), UI layers, UI clip players. Global scene settings are reset to the engine defaults (snapshotted
  at the first load, before anything is restored) before the doc's own — so older docs no longer inherit the previous
  doc's fog/PS1/SSAO/wind/skin-ramp, and legacy array-format docs get the anim-library/script/asset/player clears too.
  Tests: GARP clear, character clear, defaults reset, coordinator ordering + failure. *Not changed:* trigger volumes
  (host-supplied runtime config, not document data); orphan script behaviors on node delete (→ separate item). **M**
- [x] **P7 · 2D shape undo never cleared on load.** *Fixed 2026-09-28:* the restore now clears
  `interactionService.vectorUndo` beside `clearUndo3D`. Test in `document-state-coordinator.test.ts`. (Raster undo is
  per-layer on each layer's manager, which the load recreates — not changed.) **S**
- [x] **P8 · Submeshes (multi-material) never saved.** *Fixed 2026-09-28:* `Mesh3D.toJSON` emits `submeshes`; the
  restore applies them after the mesh rebuilds (saved slots win over a GLB re-import's defaults — they carry the
  per-slot material edits), validated by `validSavedSubmeshes` against the restored index count so a mismatched save
  is skipped, not drawn as garbage. The four submesh setters now set `stateDirty`. 3 tests. *Not checked:* the other
  toJSON gaps the audit listed (`vertexColors`, `alwaysOnTop`, billboard fields, `pickable`) — verify they're user-set
  before adding. **S**
- [x] **P9 · Saves not atomic / concurrent / not flushed on exit.** *Fixed 2026-09-28 (4 parts):* (1) **manifest
  written LAST** as the commit record — an interrupted save now leaves the previous manifest in charge (its layer
  files still exist; pruning runs after). (2) **Saves are serialized** — an explicit `saveNow()` waits for a running
  save instead of writing the same files concurrently. (3) **Per-document Web Lock** (`withDocLock`,
  `salsa-doc:<id>`) around the write, so two tabs / two instances can't interleave file-by-file. (4) **Flush on tab
  hide/close** — `visibilitychange→hidden` + `pagehide` trigger a save (was: up to 30s lost). Also (with P1):
  `enableAutoSave` destroys the old instance. 4 tests (mutation-checked). *Limitation:* not a true atomic directory
  swap (OPFS can't rename dirs) — a crash mid-save can still pair new JSON with the old manifest; the version-guard
  (P10) + a generation stamp would close it. **M**
- [x] **P10 · No real schema versioning.** *Fixed 2026-09-28:* new `schema-version.ts` — `DOCUMENT_SCHEMA_VERSION`
  (now **2**; absent = v1) stamped on every save's manifest (`manifest.schemaVersion`, separate from the pixel-format
  `version`). Load: an OLDER doc runs through `migrateDocumentPayload` (ordered pure steps; v1→v2 is additive/no-op);
  a NEWER doc still loads best-effort but is recorded as a blocking restore issue → **read-only** (saving blocked).
  Write: `writeToOPFS` reads the on-disk manifest first and refuses (and blocks saving) if a newer build wrote it —
  so an old tab can't overwrite a doc a newer tab saved. `.frogmarks` already refused newer package versions.
  8 tests. **Rule for the future:** bump the version + add a migration step whenever a change would make an older
  build lose/misread data; additive optional fields don't need a bump. **M**
- [x] **P11 · Live pose leaks into saves outside Play.** *Fixed 2026-09-28:* every `DocumentPersistence` is now built
  by `ShapeManager._createPersistence` (4 of 5 creation sites skipped the busy predicate), and the predicate also
  covers UI preview (`ui.interactive`) + Player mode — where `playAnimation`/`seekAnimation` pose skeletons. Autosave
  resumes when they end; explicit saves are unaffected. Test for the predicate contract. **S**
- [x] **P12 · Round-trip test.** *Done 2026-09-28:* `persistence-roundtrip.test.ts` — a `Required<DocumentSavePayload>`
  fixture (adding a payload field won't compile until the test covers it; non-persisted control flags must be listed in
  `NOT_PERSISTED`) proves: autosave write → load returns every section; write → load → write is byte-identical;
  `.frogmarks` yields exactly the autosave-folder payload. Mutation-checked (dropping garp.json from autosave, or
  bakedParts from the package, both fail it). *Scope:* storage paths only — the manager-level save/load (live scene →
  payload → live scene) needs the GPU and stays covered by the browser `drive-persist` harness. **M**
- [x] **P13 · Minor texture persistence gaps.** *Fixed 2026-09-28:* the raw `setMeshTexture` / `setMeshNormalMap` now
  drop the stale library id (a reload used to re-bind the OLD library texture over the raw one); restore clears a
  saved `hasNormalMap` that has no GLB or library map behind it. The misleading "stateDirty makes it persist" comment
  is corrected (raw textures are regenerated content, not persisted). GPU paths → browser-verify. **S**

## Tier 2 — Renderer robustness

- [x] **R0 · Silhouette `struct MeshInstance` was 224 bytes vs stride 240** (hover outline garbage past slot 0).
  *Fixed:* padded; `mesh-instance-layout.test.ts` now scans every renderer file (proven to fail on regression). **S**
- [ ] **R1 · No device-lost / GPU-error handling.** Zero `device.lost` / `onuncapturederror`; `"indirect-first-instance"`
  required without a feature check (`webgpu-renderer.ts:1247`). *Fix:* recover on lost, log uncaptured errors,
  feature-check, error scopes around pipeline creation. **M**
- [ ] **R2 · Planar mirror + resize submits a destroyed texture** (bind group built before `_planarTex` is
  reallocated, `renderer-3d.ts:2274` vs `2763`). Drops whole frames while resizing. *Fix:* resize planar targets
  before `_ensureMeshBindGroups`. **S**
- [ ] **R3 · Shadow + mirror passes reuse the camera-culled list** (`renderer-3d.ts:2385,2441`). Off-screen casters
  lose their shadows; mirrors miss what's behind the camera. *Fix:* cull per pass (light box / mirrored frustum). **M**
- [ ] **R4 · GPU cache leaks.** Nested-group deletes only evict direct children (`scene3d-manager.ts:3134,5882`);
  document switch evicts nothing; outline shells go stale on geometry edit; planar targets never freed;
  `Renderer3D.destroy()` never called and incomplete. *Fix:* walk descendants, `resetScene()` on reinitialize, finish
  `destroy()`. **M**
- [ ] **R5 · Skinned-only scenes skip every pre-pass** (shadow/SSAO/planar live inside `drawMeshes`,
  `webgpu-renderer.ts:2206`). *Fix:* hoist the pre-passes. **S–M**
- [ ] **R6 · `render()` is async, un-awaited, not re-entrancy guarded** (`webgpu-renderer.ts:461,482`). *Fix:*
  in-flight flag + `.catch`. **S**
- [ ] **R7 · Source-link highlight = 3 draws per array instance** (18K instances → ~54K draws/frame,
  `renderer-3d.ts:3148`). *Fix:* one entry with `instanceCount`. **S**
- [ ] **R8 · Per-frame allocation churn:** hover path spreads/filters all draw lists per frame (`renderer-3d.ts:3075-3137`
  + its own submit); planar pass unbatched; `_ensureSkinnedVBIB` recreates buffers every `skinDirty` frame. **M**
- [ ] **R9 · Instance slots overloaded per feature** (`_writePatternSlots` reuses floats 48–55 for 6 features; ground
  overwrites `specularColor`). Replace magic offsets with a typed, named-offset writer. **M**
- [ ] **R10 · ResizeObserver only watches the first canvas** (`webgpu-renderer.ts:1107`); no clamp to
  `maxTextureDimension2D`. **S**

## Tier 4 — Architecture

- [ ] **A1 · Keep the ShapeManager façade — no rewrite.** *Decision 2026-09-28:* the one-line forwards are a
  legitimate stable API for Frogmarks; rewriting them has no payoff. (~63% of ShapeManager / ~60% of scene3d-manager
  are one-line forwards; ~273 chain 3 levels deep.) What to do instead:
  - **Rule, effective now:** new features forward ShapeManager → sub-module directly; don't add a scene3d-manager
    middle hop. Leave existing chains alone until touched.
  - Forwards must preserve types — no `as any` inside the façade (e.g. `setMeshKeyframe3D` at `shape-manager.ts:8965`).
  - The breakage protection the façade is meant to give only works once Frogmarks stops bypassing it — see **T6**. **S**
- [ ] **A2 · Prune unused public API — deprecate first, delete later. Do LAST, after T6.** ~270 of ~1,331
  ShapeManager public methods are called by nobody. Verify each against Frogmarks + the scene-authoring API, mark
  `@deprecated`, delete in a later pass. Also remove existing deprecated aliases + the orphaned `@deprecated` block
  (`scene3d-manager.ts:5602`). **M**
- [ ] **A3 · Stop new features landing in the façades.** Recent additions (locomotion, script behaviors, animation
  library, shading) went straight into scene3d-manager. Move them to sibling modules; add a member-count guard test. **M**
- [ ] **A4 · Split the renderer god objects.** `Renderer3D` (281 private fields), `WebGPURenderer.render()` (495
  lines) → per-pass modules. **L**
- [ ] **A5 · One shared WGSL struct.** 13 copies of `MeshInstance`, 15 of `SceneUniforms`. Export one snippet each and
  interpolate (ssao already does). **S–M**
- [ ] **A6 · Debug globals ship in the library.** 24 `window.*` assignments, no `import.meta.env.DEV` guard;
  `ShapeManager.instance` never reset. Move to `src/dev/`, add `dispose()`. **S**
- [ ] **A7 · Layering.** Renderer imports ~49 service modules; 20+ shapes import `InteractionService` for z-index;
  `CacheService` + `mesh-generators` in the wrong layer. **M**
- [ ] **A8 · Duplicates / inconsistency.** `setRetroPreset3D` duplicated; two material-mutation styles; naming
  (`setMeshMaterial` vs `setMeshRoughness3D`); two unrelated `WorldManager` classes. **S–M**

## Tier 5 — Character system

Measured: 2,928 verts / 5,330 tris / 20 joints; **76% of verts on unarticulated 24-gon digits**, arms 8-sided, head
9 rings; **88% of verts bound to a single joint**, max 2 influences, hand-set per-ring constants.

- [ ] **C1 · Computed skin weights** — smooth falloff along each bone, 3–4 influences, a chest→clavicle→shoulder
  gradient at the socket; fit clothing in the pose actually shown. Fixes the shoulder/armpit collapse in the default
  Relaxed pose (77°); clothing inherits it. Topology unchanged → saves/blend shapes stay valid. Needs a posed-weight
  test. **M · biggest visual win**
- [ ] **C2 · Fix character import/export.** `importCharacter3D` only applies `top`/`bottom` (drops shoes, socks,
  undershirt, underpants; doesn't remove absent slots); export omits skin tone, eyes/face, attachments
  (`shape-manager.ts:7385-7406`). **S**
- [ ] **C3 · One `CharacterSpec`** — `{ body, skinTone, face/eyes, hair, clothing (all slots), attachments,
  renderStyle, seed }` with a single `applyCharacterSpec`; body presets (male/child/chibi/athletic) as data; the
  seeded randomizer from character-variety.md. **M**
- [ ] **C4 · Rebalance topology** — 12–16-sided arms, 4–6-sided digits welded to the palm (removes 480 open edges),
  denser head. Move hardcoded 24-gon column indices to `COL_*`-relative first. Vertex count changes → stored blend
  shapes drop. **M**
- [ ] **C5 · Template head** — ears, eye sockets, mouth line, real nose, clean face UVs; face variety via morph
  targets (already plumbed); jaw + eye joints; eye decal onto the head's own UVs. Biggest jump in "character-ness".
  **L**
- [ ] **C6 · Hair & skirt motion** — spring chains (or head→neck→chest blended weights) for long scalp hair (currently
  rigid, swings through shoulders); fit hair to the real head surface, not a bbox ellipsoid; blended hip→leg skirt
  weights + spring hem. **M**
- [ ] **C7 · Refit cost** — share one `BodyFit` across all overlays; update meshes in place instead of
  destroy/recreate (also stops mesh-ID churn); memoize gaze re-render (full 1024² canvas per call). **M**
- [ ] **C8 · Grouping gaps** — charms missing from `overlayMeshIds` (`scene3d-character.ts:1559`); kitbash parts
  still don't move as a group. **S–M**
- [ ] **C9 · Character tests** — clothing/hair/attachment/eye generators have zero tests; add export/import
  round-trip + posed-deformation checks. **M**
