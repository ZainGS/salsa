# Salsa — Project Evaluation (2026-09-02)

Multi-agent audit (read-only): a correctness/bug sweep across four file areas, an architecture/tech-debt assessment, a high-value-missing-features pass, and a City Edit Mode status check. Everything below is verified against live code with `file:line` refs. Severities are the agents'; I've de-duplicated and grouped by theme, then given a prioritized do-next list.

---

## TL;DR — the three things that matter most

1. **GPU resource leaks are the top live-bug cluster.** Painted mesh textures, character-swap caches, and delete paths orphan `GPUTexture`/BVH handles that are never `destroy()`'d — VRAM climbs across an editing session until device-loss. Several share one clean fix (an owning teardown for `_uvPaintTextures`).
2. **The renderer is now the god-object frontier, and its async `render()` has a re-entrancy hazard.** `scene3d-manager` decomposition worked (−44%), but the mass *relocated* into `webgpu-renderer.ts` (5,240 ln, growing) + `renderer-3d.ts` (4,649 ln, growing), which have no extraction started — and `render()` being `async` + un-awaited + un-guarded can corrupt frames when the async-dither/capture/resize paths interleave.
3. **You're one connector from "playable."** Trigger volumes (just built) + the UI System's already-complete action/state vocabulary = walk-into-zone → game logic. The next unlocks after that are an interaction ("use") verb and `.frogcart` export + Player (the ship/share story, whose renderer half already exists in the Salsa Viewer).

## 1. Correctness & bugs

### 🔴 Critical — GPU resource leaks (fix soon; VRAM → device-loss)

| # | Bug | Where | Fix |
|---|-----|-------|-----|
| B1 | **`_uvPaintTextures` managers never `destroy()`'d** — every painted/uploaded mesh texture leaks; map is never cleared on reload. | `shape-manager.ts:213` (decl); removals `:4773/:7749/:7703`; reload `:13400-13423` | One owning teardown (destroy-on-remove + clear-with-destroy on reload), called from `deleteMesh3D`, `clearPartTexture3D`, `deleteProceduralBody3D`, `restoreDocumentState`. Closes B1+B2. |
| B2 | **`deleteMesh3D` leaks the uv-paint entry AND bloats every save** — dead id passes the serialize skip-checks, so an orphan PNG is written to every save and silently dropped on load. | `shape-manager.ts:4731-4739`, serialize `:13052-13066` | (same teardown as B1) |
| B3 | **`swapCharacterSlot` leaks picker BVH + skinned GPU buffers** for the removed part — omits the `_picker.evictMesh` / `renderer3D.evictMeshCaches` that `deleteMesh` does. Unbounded VRAM per hair/top/etc. swap. | `scene3d-manager.ts:4382-4389` (cf. `:5750-5751`) | Add the same eviction calls on slot swap. |
| B4 | **`deleteSelectedShapes` leaks cache slots for non-selected descendants** — deletes the subtree but only deallocates the top-level (group) cache entry. | `shape-manager.ts:11543-11566` | Recurse `deallocateCacheEntries` over removed descendants. |

Minor: `RasterLayerManager` has no `destroy()` → cached `_readbackBuf` GPUBuffer never freed (`raster-layer-manager.ts:1053`); `deleteMesh` undo command has no `dispose` to free unshared textures (`scene3d-manager.ts:5780`, speculative — depends on per-mesh vs library ownership).

### 🔴 Critical — async `render()` concurrency (intermittent black/garbled frames)

The root cause cluster: `render()` is `async` (`webgpu-renderer.ts:2864`), fired **un-awaited** from the rAF loop (`:439`, `:460`) with **no re-entrancy guard**, while it has real `await` points (`compositeAsync` `:2977/:3379`, and the artboard captures).

| # | Bug | Where | Note |
|---|-----|-------|------|
| B5 | Two `render()` executions interleave (error-diffusion dither + panning) → share `webGPURenderStrategy` + `stagingBuffer` → clobbered draw uploads. | `:439/:460` + `:2977` | Add a `_rendering` guard / coalesce, or make the loop await. |
| B6 | `getCurrentTexture()` captured at top of `render()` then written *after* an await → expired-swapchain-texture writes. | `:2905` used at `:3473/:3493` | Re-acquire after the await, or don't await between acquire and use. |
| B7 | Resize during the await → `copyTextureToTexture` extent mismatch, or `ensureLastFrameTex` destroys the open pass's color target. | `:3473-3486`, `:4704-4722` | Same fix as B5 (no overlapping frames). Speculative but same root. |
| B8 | **Artboard capture doesn't pause the loop → `_captureMode` bleeds onto concurrent loop frames** (on-screen stall; wrong-frame thumbnail). Also the refraction grab is overwritten during capture (`:3481`, one-frame glass glitch). | `:5104-5111`, `:5230-5237`, `:3481` | *(introduced by the textured-artboard capture — mine.)* Pause/suspend the loop around capture, and guard the grab copy with `!_captureMode`. |

Also: no `device.lost` / `onuncapturederror` handling anywhere → a GPU reset = permanent black canvas with no recovery/surfacing.

## 2. Architecture & tech-debt

**Landed since the 2026-08-17 review** (verified): pingTex crash fix (`brush-stamp-pipeline.ts:451`), `debugSnapshots=false`, build-order de-duplication (`src/world/build-order.ts` + guard test), generator-invariant tests. Discipline is unusually high: **0 `@ts-ignore` across ~154k lines**, ~9 benign TODOs, every `as any` a bounded boundary cast.

**God-object scorecard (live):**

| File | Aug-05 | Now | Trend | Verdict |
|---|---|---|---|---|
| `shape-manager.ts` | 14,245 | **14,011** | flat | Worst by mass — but a *fat facade* (~1,160 methods, half thin delegators), not a logic tangle. |
| `webgpu-renderer.ts` | 4,998 | **5,240** | **growing** | Worst by cohesion: 3D render loop + ALL 2D pointer input + compositor. `handlePointerDown` ~579 ln. No extraction started. |
| `renderer-3d.ts` | 4,487 | **4,649** | **growing** | Mega-methods: `uploadMeshInstances` ~980 ln, `drawMeshes` ~707, `uploadSceneUniforms` ~422. |
| `scene3d-manager.ts` | 15,267 | **8,572** | **−44%** | Best-managed — 20+ `scene3d-*` siblings on `ManagerContext`. The decomposition template *works*. |

**Headline:** decomposition *relocated* the god-object mass out of the service layer and **into the renderer**, which now holds the two fastest-growing single-file concentrations with no plan pointed at them. Other smells: ~37 gl-matrix `as Float32Array` casts in `renderer-3d`; renderer duck-typing scene nodes via `as any`; `raster-texture-manager.ts` still carries a **dead duplicate** brush compute shader + snapshot stack (~40% of the file); `world-manager.ts` (3,166 ln, ~17 responsibilities) undecomposed.

**Test-coverage gaps (high-risk, untested):** the ~700–980-line renderer upload/draw methods (slot reuse / dirty flow) have no characterization tests; 2D pointer input (~1,600 ln) has zero tests; 3D document restore (`recreateNode`/`gather`/`restore`, ~1,150 ln — the "4-restore-bug saga" path) is not round-trip tested.

**Ranked opportunities** (top of the list): ① **type the gl-matrix bridge** (S, kills ~40 casts); ② **delete `raster-texture-manager` duplication** (M); ③ **mock-GPUDevice characterization tests for `uploadMeshInstances`/`uploadSceneUniforms`** (M, the safety net); ④ **extract 2D input → `RasterInteractionController`** (L, highest structural ROI — the renderer is the growing frontier); ⑤ split `renderer-3d` mega-methods (L, after ③); ⑥ 3D-restore round-trip tests (M); ⑦ extract `scene3d` animation cluster (~1,500 ln, L); … **Fund-only-three:** ①, ④, ③.

On use, an `interact` transition auto-dispatches into the UI state machine (+ optional `sm.setInteractHandler3D` raw hook). ## 4. City Edit Mode — status & recommendations

"City Edit Mode" = `WorldManager.enterCityMode()` (`world-manager.ts:1201-1249`), an orbit workspace with a lighting scope. The `city-visual-upgrade.md` thesis: reach the anime aerial look at the current zoom by stacking atmosphere + lighting + grade + density.

**Key finding: the expensive renderer primitives for Phases 1–4 are mostly BUILT, but the City-Edit *integration + persistence + authoring-UI* layer is largely missing** — the best stuff is opt-in dev toggles, not the default authored look.

| Piece | Status |
|---|---|
| City Edit Mode + lighting scope, distance fog, soft shadows, color-grade stack, **glass material**, foliage wind/translucency | ✅ Built |
| Aerial-perspective fog | ⚠️ Cheap version built (desaturate-to-fog) but **not auto-applied/persisted in City Edit Mode** + no graded blue-shift/height term |
| SSAO | ⚠️ **Full renderer feature built, but ZERO wiring into City Edit Mode** — not auto-enabled, not persisted in `worldParams.lighting`, not in the lighting scope |
| Sky gradient | ⚠️ 2-stop only; no sun disk/halo, no multi-stop |
| Hemisphere sky ambient (2C), god rays, lens flare, richer/parallax clouds, skyline-density knobs | ❌ Not built |
| Street-level detail (Phase 6) | ⏸ Correctly deferred (gated on a street camera that doesn't exist; ground/foliage material substrate IS built, just not revealed by a near-LOD camera) |

**Top remaining work (mostly S/M — unlocks already-paid-for capability):**
1. **Wire SSAO into the City-Edit lighting scope** (S/M) — auto-enable + persist + restore. *Highest leverage-per-effort in the whole pass — the biggest "grounded not floating" cue is built but invisible.*
2. **Auto-apply + persist aerial fog in City Edit Mode** (S) — the spec's "#1 win"; shader/API exist, only fires via a manual toggle.
3. **Sky-colour hemisphere ambient** (M) — blue shadows / warm lit-sides, the core anime-lighting read.
4. God rays (M/L), richer sky + sun disk + parallax clouds (M/L), skyline-density knobs (M).

**Improvements beyond the spec:** persist a single serialized `worldParams.lighting` block (sun azimuth + ssao + aerial + sky/grade overrides) so a saved city reloads its look; **height-based fog** (cheap `worldPos.y` term — bigger depth win than god rays); **cloud shadows** (scrolling noise × sun term); reflect the **sky keyframes** in glass (not just `fogColor`); a golden-hour one-tap preset + draggable sun-azimuth compass; a mid-zoom LOD tier that reveals the built ground/foliage materials before a full street camera exists.
